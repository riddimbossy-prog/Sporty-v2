# v21.5.4 — Verified public-slip gate

## Problem confirmed

v21.5.2 discovered 20 code-like values but returned zero tips. It still saved those candidates, producing empty cards and unrelated totals in Supabase.

## Fix

- Generic object `code` properties are no longer trusted without slip evidence.
- React-controlled booking-code inputs are updated with their native setter and value tracker.
- Input/change events, button submission, form submission and Enter fallback are supported.
- All configured candidates are expanded, up to the workflow limit.
- A candidate is publishable only after expansion returns at least one valid fixture, market and pick.
- Zero-tip auto-collected rows are filtered immediately from the public API.
- The next workflow deletes zero-tip and invalid legacy auto-collected rows from Supabase.
- Public collector status distinguishes discovered candidates from verified slips.
- Request diagnostics expose only method, path and request-key names—never cookies, tokens or submitted values.

## Expected behavior

The feed may temporarily become empty after deployment. That is intentional when no candidate can be verified. Fake or unexpanded codes are never substituted for real slips.
