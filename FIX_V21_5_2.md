# Sporty.codes v21.5.3 — Code quality gate

The external browser collector was working, but broad JSON scanning accepted application response objects as booking codes and sometimes treated unrelated numbers as total odds.

## Fixed

- Rejects non-primitive code values such as `[object Object]`.
- Requires auto-collected codes to contain letters and digits and be 5–8 characters.
- Blocks application words such as `OBJECTOBJECT`, `SUCCESS`, `ERROR`, `REQUEST`, and `RESPONSE`.
- Requires generic `code` fields to have booking-slip evidence in the same object.
- Reads total odds only from total/combined-odds fields, not generic selection odds.
- Validates selection counts and individual odds.
- Recalculates a suspicious total from the product of validated leg odds.
- Filters invalid legacy rows from the public API immediately.
- Deletes invalid auto-collected rows during the next GitHub Actions collector run.
- Removes harmless Chromium DBus/GCM noise from public diagnostics.

No Supabase migration is required.
