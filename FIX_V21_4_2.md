# sporty.codes v21.4.2 — Code Hub page collector fix

## Fixed

- Uses the exact public Code Hub page: `https://www.sportybet.com/gh/m/code-hub/codes`.
- Parses server HTML, embedded JSON state, JSON.parse payloads, and booking-code data attributes.
- Extracts public six-character code, total odds, and selection count when present.
- Bumps event and Code Hub cache namespaces so earlier empty responses are not reused.
- Empty feeds are cached for no more than 60 seconds.
- Adds `POST /api/admin/refresh-codes` to force a Code Hub refresh only.
- Adds Code Hub extraction diagnostics to `GET /api/source-status`.
- Returns public collection errors in `/api/get_code_hub_codes` instead of hiding them.

## No database migration

The existing migrations 001–007 remain valid. No new SQL is required.

## First refresh after deployment

```powershell
$headers = @{ Authorization = "Bearer YOUR_CUSTOM_API_ADMIN_TOKEN" }
Invoke-RestMethod -Method Post -Uri "https://sporty-codes-staging.onrender.com/api/admin/refresh-codes" -Headers $headers
```

Then open:

- `/api/get_code_hub_codes`
- `/api/source-status`
- `/marketplace.html`

The live SportyBet page must expose the codes in public server HTML or embedded public page state. The collector does not use account cookies, login access, or CAPTCHA bypasses.
