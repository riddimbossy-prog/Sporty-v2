# v21.5.2 — Render 502 and collector reset fix

## Root cause

The Render service successfully installed Chromium, but launching it inside the web process exceeded the available runtime resources. Render restarted the service, which reset the in-memory collector status to null and temporarily returned 502 Bad Gateway.

## Fix

- Removed Chromium execution from the Render web process.
- Changed the Render Blueprint to a lightweight Node runtime.
- Added a scheduled/manual GitHub Actions browser collector.
- Added a standalone browser sync script.
- Persisted collector status in Supabase `api_cache`.
- Kept booking-code and selection storage in the existing Supabase tables.
- Disabled accidental browser launch by default.
- Protected the old Render collector route with a clear 409 response.

No new SQL migration is required.
